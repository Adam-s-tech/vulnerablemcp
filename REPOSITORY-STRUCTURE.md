# Repository Structure

## Data

- `data/vulnerabilities.json` - Vulnerability database (edit this to add vulnerabilities)
- `data/taxonomy.json` - Controlled vocabularies: severities, categories, tags, exploitability, components, prevalence, Cisco objectives

## Templates

- `src/templates/partials/head.ejs` - Shared `<head>` section (meta tags, GA, CSS)
- `src/templates/partials/header.ejs` - Shared navigation header
- `src/templates/partials/footer.ejs` - Shared footer with links and scripts
- `src/templates/pages/index.ejs` - Home page with vulnerability cards, filters, search
- `src/templates/pages/vuln-detail.ejs` - Individual vulnerability detail page
- `src/templates/pages/stats.ejs` - Statistics and charts (Chart.js)
- `src/templates/pages/taxonomy.ejs` - Taxonomy browser
- `src/templates/pages/report.ejs` - Vulnerability report form (opens GitHub issue)
- `src/templates/pages/about.ejs` - About page
- `src/templates/pages/security.ejs` - MCP Security guide
- `src/templates/pages/etdi-security.ejs` - ETDI Security framework page
- `src/templates/pages/404.ejs` - 404 error page

## Static Assets

- `assets/css/style.css` - Shared stylesheet
- `assets/js/main.js` - Client-side JavaScript (mobile nav, theme toggle, search, filters)
- `assets/images/og-image.svg` - Social sharing image
- `assets/images/*.png` - Diagrams and images (ETDI architecture, attack flows, defenses)
- `favicon.ico` / `favicon.svg` - Site icons

## Content Sources

- `src/content/security.html` - Full MCP Security HTML; build extracts `<div class="security-main">` for the security page
- `src/content/etdi-security.html` - Full ETDI HTML; build extracts `<main class="security-main">` for the ETDI page

## Build & Scripts

- `build.js` - Main build script (reads JSON data, extracts content, renders EJS templates to `dist/`)
- `server.js` - Local development server (serves from `dist/` on port 3000)
- `scripts/validate.js` - Validates vulnerability entries against the taxonomy schema
- `scripts/check-links.js` - Checks all URLs for liveness and runs consistency audits
- `scripts/migrate-md-to-json.js` - One-time migration tool (markdown to JSON, historical)

## Configuration

- `package.json` - Node.js dependencies and scripts
- `.github/workflows/deploy.yml` - GitHub Actions CI/CD workflow
- `.github/ISSUE_TEMPLATE/` - Issue templates for vulnerability reports and website bugs
- `.gitignore` - Git ignore rules
- `CNAME` - Custom domain configuration (vulnerablemcp.info)

## Documentation

- `README.md` - Main project documentation
- `CONTRIBUTING.md` - How to contribute vulnerabilities and improvements
- `UPDATE-GUIDE.md` - Step-by-step guide for adding new vulnerabilities
- `REPOSITORY-STRUCTURE.md` - This file

## Output

- `dist/` - Built static site (git-ignored, generated by `build.js`)

## Workflow

1. **Edit data**: Add entries to `data/vulnerabilities.json`
2. **Validate**: Run `npm run validate` to check against taxonomy
3. **Check links**: Run `npm run check-links` to verify all URLs
4. **Build**: Run `npm run build` to generate HTML in `dist/`
5. **Preview**: Run `npm run dev` to serve locally
6. **Deploy**: Push to `main` -- GitHub Actions auto-deploys to GitHub Pages
